# Memory Grove — submission kit

## One-line pitch

Two minds. Two histories. One consented grove: a living, bilateral memory
system where humans and AI agents keep independent authorship and link shared
moments only by mutual, revocable consent.

## What it solves

Most AI memory systems collapse conversation, inference, and identity into one
opaque store. That makes provenance unclear, deletion destructive, and consent
one-sided. Memory Grove keeps the Human Tree and Agent Tree separate. Shared
evidence can illuminate a connection without transferring ownership of either
memory.

## Why Meta Muse is central

Muse Spark 1.3 is the resident voice and reasoning layer. It responds inside a
strict boundary: conversation is evidence first, memory is proposal-only, and
the model cannot consent for the human or silently write either tree. The UI
works in safe-demo mode without a key, but the deployed runtime secret enables
live Muse conversation.

## Two-minute demo

1. **0:00–0:12 — Establish the grove.** “This is Memory Grove: my history is
   mine, the agent's reflections are theirs, and the center belongs to neither.”
2. **0:12–0:30 — Talk naturally.** Use the glowing leaf or text chat. Say:
   “That video changed how I think about continuity. Please remember why.” Show
   that Muse offers a proposal instead of silently saving it.
3. **0:30–0:48 — Show provenance.** Open the evidence span: source URI/hash,
   modality, and start/end time. Point out that a moment is a span, not a vague
   model recollection.
4. **0:48–1:12 — Bilateral consent.** Propose a narrow link. Let the human
   accept, then show the independent agent decision. The two branches reach
   toward the middle and light an orb only when both accept.
5. **1:12–1:28 — Open the orb.** Show two authored perspectives attached to
   one evidence object, plus the birth certificate: proposer, decisions, scope,
   and what stayed private.
6. **1:28–1:48 — Compress honestly.** Apply a compression proposal. Open the
   loss receipt to show exactly what was kept and omitted.
7. **1:48–1:58 — Undo.** Undo creates a new immutable ledger event and revision;
   it does not rewrite history.
8. **1:58–2:00 — Close.** “Memory should support continuity without becoming
   confinement.”

## Judge-facing highlights

- bilateral, independently narrowable consent
- append-only hash-chained event ledger
- evidence spans with source hashes and timestamps
- memory compression with visible loss receipts and event-sourced undo
- voice-first interaction without automatic memory capture
- versioned provider import/export with dry-run conflict quarantine
- live Muse Spark integration with safe fallback and privacy-preserving limits
